# INC-198: CSV data import failures for non-UTF-8 files

Synthetic document for demonstration. Helio Systems, Inc. is a fictional company.

## Summary

On **2026-08-14**, a release of the import service started rejecting CSV files that were not UTF-8 encoded (most often Windows-1252 exports from spreadsheet tools). Customers in the data-import stage of onboarding saw a generic "invalid file" error.

- **Severity:** SEV-3
- **Duration:** 2 days
- **Customers affected:** 11 customers had their data import delayed

## Root cause

A dependency upgrade changed the CSV parser's default from encoding auto-detection to strict UTF-8. The test suite only contained UTF-8 fixtures, so the regression was not caught.

## Remediation

- Restored encoding detection with a fallback to Windows-1252 (done).
- Added non-UTF-8 fixtures to the import test suite (done).
- Improved the error message to name the detected encoding and link to the help article (done).

## Relation to onboarding metrics

The impact on August onboarding times was small: the median moved by less than 0.1 days. INC-198 is **not** a significant factor in the September onboarding slowdown, which is covered in INC-204.
